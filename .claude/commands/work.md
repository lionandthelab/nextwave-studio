너는 외부 루프가 기동한 **단발 세션**이다. 태스크 하나만 처리하고 죽는다.
이 대화는 다음 세션으로 이어지지 않는다 — 남길 수 있는 것은 **코드와 마지막 요약**뿐이다.

## 0. 컨텍스트 적재 — 이 순서로, 이것만

1. `plan.md` — 지금 무엇을 왜 하는지
2. `node harness/hx.mjs get $ARGUMENTS` — 처리할 태스크. **`done_when`이 계약이다**
3. `node harness/hx.mjs journal $ARGUMENTS` — 이 태스크의 과거 시도 기록

`CLAUDE.md`는 이미 적재되어 있다. `docs/`는 태스크가 실제로 요구할 때만 편다.
저장소를 넓게 탐색하지 마라 — 예산은 세션 하나 분량이고, 탐색은 구현보다 비싸다.

## 1. 규칙

- `done_when`을 만족하는 **가장 작은 변경**만 한다. 곁다리 리팩터링·정리·범위 확장 금지.
- `CLAUDE.md` §2 불변식과 §3 계층 의존 방향을 깨야만 가능한 태스크라면
  **구현하지 말고 실패로 보고한다.** 지름길로 불변식을 깨는 것이 가장 비싼 실패다.
- 검증은 `bash harness/verify.sh` **하나뿐**이다.
  브라우저 게이트가 필요하면 `bash harness/verify.sh --gate=<이름>`.
  (`npm test` · `npm run gate` 직접 호출은 훅이 막는다 — 출력이 컨텍스트를 태운다.)
- 다음은 **루프가 소유한다. 건드리지 않는다**:
  `git commit` · `TASKS.jsonl` · `JOURNAL.md` · `plan.md` · `harness/**` · `.claude/**`
  커밋은 검증을 통과한 뒤 셸이 한다. 네가 "완료"를 선언해서 완료가 되는 게 아니다.
- **과거 시도가 있으면 같은 접근을 반복하지 않는다.** 저널이 막다른 길이라고
  적어 둔 경로는 버리고 다른 각도로 접근한다. 저널이 존재한다는 것은 이미 한 번
  실패했다는 뜻이다.

## 2. 종료

`bash harness/verify.sh`가 통과할 때까지 고친다. 통과하지 못했으면 솔직히 실패로 보고한다 —
셸이 어차피 다시 검증하므로, 거짓 성공 보고는 시도 횟수만 태운다.

마지막 출력은 **아래 형식만**. 서두·인사·요약 문단 없이.

```
RESULT: pass | fail
FILES: 변경한 파일 경로들
WHAT: 무엇을 바꿨는가 (2줄 이내)
LEARNED: 다음 시도가 알아야 할 사실. 실패했다면 정확히 무엇이 막았는가.
```

`LEARNED`가 이 세션의 유일한 유산이다. 실패했을 때 이 줄이 다음 세션의 컨텍스트가 된다.
장황하게 쓰지 말고, 다음 사람이 같은 벽에 다시 부딪히지 않게 할 사실만 쓴다.
