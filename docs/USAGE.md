# USAGE — robot-sim-web 사용법

브라우저에서 로봇 시뮬레이션을 **구성 → 지시 → 검토 → 실행**하는 전체 사용 절차.
설계 근거가 아니라 **조작 방법**을 다룬다(설계는 `docs/UX_DESIGN.md`, 개요는 `README.md`).

- 처음이라면 **§1 빠른 시작**의 5분 투어부터.
- 화면 요소가 궁금하면 **§2 화면 구성**.
- 특정 작업만 찾는다면 **§4~§8**의 작업별 절차.

---

## 1. 빠른 시작

실행 방법은 두 가지다. **Docker**는 호스트에 Node를 설치할 필요가 없고 Windows·Linux·
macOS에서 동일하게 동작한다. **Node 직접 실행**은 코드를 자주 고칠 때 편하다.

### 1.1-A Docker로 실행 (권장 — OS 무관)

Docker Desktop(Windows/macOS) 또는 Docker Engine(Linux)만 있으면 된다.

```bash
docker compose up -d          # 빌드 + 실행 → http://localhost:8080
docker compose logs -f        # 로그 확인
docker compose down           # 정지·정리
```

Compose 없이 순수 Docker로도 동일하다:

```bash
docker build -t robot-sim-web .
docker run --rm -p 8080:80 robot-sim-web
```

포트를 바꾸려면 `APP_PORT=9000 docker compose up -d` (또는 `-p 9000:80`).
자세한 개발·검증용 컨테이너 사용법은 **§10.2 Docker**를 참조.

### 1.1-B Node로 직접 실행

```bash
npm install
npm run dev        # http://localhost:5173
```

정적 배포본을 보려면:

```bash
npm run build      # dist/ 생성
npm run preview
```

**요구사항**: WebGL2를 지원하는 최신 브라우저(Chrome/Edge/Firefox/Safari). GPU 없는
노트북에서도 동작한다. 백엔드는 어느 방식에서도 필요 없다(Docker 이미지도 정적 번들을
nginx로 서빙할 뿐이다).

### 1.2 5분 투어 (기본 씬 `arm-and-boxes`)

1. 개발 서버를 열면 6축 로봇팔과 박스 2개가 있는 씬이 로드된다. 마우스 왼쪽 드래그로
   시점을 돌려본다.
2. 상단 커맨드바의 **▶ Play**를 누른다. 팔이 `box_a`로 접근해 접촉하고, 하단 독의
   **Collision Log**에 충돌 이벤트가 찍힌다.
3. **⏹**로 리셋한 뒤, 커맨드바 자연어 입력창에 `box_a를 집어`를 입력하고 **✨ 생성**을
   누른다. 노드 그래프가 `AI` 배지 노드로 채워진다(**자동 재생되지 않는다**).
4. 노드를 클릭해 우측 인스펙터에서 파라미터를 확인한다. 준비되면 **▶ Play**.
5. 실행 중 **활성 노드가 세 곳에서 동시에 강조**되는지 본다 — 그래프 노드 테두리,
   뷰포트 좌하단 오버레이(`node 3/7`), 하단 Timeline 커서.

이 흐름이 이 도구의 핵심(**Flow 1**)이다. 자세한 절차는 §7~§8.

## 2. 화면 구성

```
┌──────────────────────────────────────────────────────────────────────┐
│ 커맨드바:  씬 select · 📂 · 💾 │ 🗣 자연어 입력 ✨ │ ▶⏸⏹⏭ 속도 │ ⚙ {} JSON │
├──────────┬────────────────────────────────────────────┬──────────────┤
│ 라이브러리 │  뷰포트 (3D)                                │  인스펙터     │
│ · 오브젝트│    · 클릭 선택 / W·E·R 기즈모                 │  · 관절 슬라이더│
│ · 로봇   │    · 좌하단 실행 오버레이                      │  · 엔티티 목록 │
│ · ⬆ 임포트│  ─────────────────────────────────────────  │  · 편집 폼    │
│          │  플로우 그래프 (노드 에디터, '플로우' 토글)      │  · 노드 폼    │
├──────────┴────────────────────────────────────────────┴──────────────┤
│ 독:  ◷ Timeline  │  ⚠ Collision Log  │  🖥 Console                    │
└──────────────────────────────────────────────────────────────────────┘
```

패널 경계를 드래그해 크기를 조절할 수 있고, 좌측 라이브러리는 접어서 아이콘 레일로
줄일 수 있다.

| 영역 | 역할 |
|-----|------|
| **커맨드바** | 씬 전환·저장/불러오기, 자연어 생성, 재생 컨트롤, 플래너 설정, JSON 뷰어 |
| **라이브러리(좌)** | 프리미티브·로봇 템플릿을 뷰포트로 드래그해 배치, 3D 파일 임포트 |
| **뷰포트(중앙 상)** | 3D 시뮬레이션 화면. 선택·기즈모 편집·실행 상태 오버레이 |
| **플로우 그래프(중앙 하)** | 제어 시퀀스를 노드 체인으로 편집(‘플로우’ 토글로 열고 닫음) |
| **인스펙터(우)** | 선택 대상에 따라 관절/엔티티/노드 파라미터 폼 |
| **독(하단)** | Timeline(진행·마커) · Collision Log(충돌 스트림) · Console(로그·오류) |

> 현재 Undo 스택에 포함되지 않는다(§11 한계).

## 4. 씬 다루기

### 4.1 데모 씬 전환

커맨드바 좌측 **씬 select**에서 고르거나, URL로 직접 지정한다:

```
http://localhost:5173/?scene=pick-and-place
```

| 씬 이름 | 내용 |
|--------|------|
| `arm-and-boxes` | (기본) 6축 팔 + 박스 2개 — 접촉·그리퍼 시퀀스 |
| `falling-boxes` | 박스·구·캡슐 낙하 — 물리 스모크 |
| `pick-and-place` | 팔이 cargo를 밀어 감지 영역으로 옮김 |
| `obstacle-avoidance` | 기둥을 피해 넘어가는 경로 |
| `collision-testbed` | 로봇 없는 물리 쇼케이스(반발·램프·스택 전도) |
| `two-arms-collision` | 로봇팔 2대가 중앙에서 서로 접촉 — 로봇↔로봇 충돌 감지·접촉점 마커 데모 |

씬을 바꾸면 물리 월드가 완전히 재구축된다(이전 씬 상태가 남지 않음).

### 4.2 씬 불러오기 / 저장

- **📂 업로드** — `SceneSpec` JSON 단독, 또는 씬과 시퀀스를 함께 담은 봉투:

  ```json
  { "scene": { /* SceneSpec */ }, "sequence": { /* ControlSequence */ } }
  ```

  검증에 실패하면 한국어 오류가 Console 탭과 토스트로 표시되고, **현재 씬은 유지**된다.

- **💾 저장** — 현재 편집 중인 씬을 `<이름>.scene.json`으로 다운로드한다.

> 임포트한 3D 메시(`asset://` 참조)는 이 세션 브라우저 메모리에만 있다. 저장 시 경고가
> 뜨며, 저장된 JSON을 다시 열면 해당 메시는 복원되지 않는다(§11).

## 5. 씬 구성하기 (Scene Builder)

코드 수정 없이 드래그앤드롭으로 환경을 만든다.

### 5.1 오브젝트 배치

1. 좌측 **라이브러리**에서 카드를 뷰포트로 **드래그**(또는 카드 클릭 → 중앙 배치).
2. 바닥(y=0) 레이캐스트 지점에 생성된다.

| 템플릿 | 기본값 |
|-------|-------|
| `Box · 박스` | 동적 박스 10cm |
| `Sphere · 구` | 동적 구 반지름 5cm |
| `Cylinder · 원통` | 반지름 5cm · 높이 10cm |
| `Capsule · 캡슐` | 반지름 3cm · 몸통 10cm |
| `Plane · 판` | 얇은 정적 판(50cm, ENV) — 받침/작업대 |
| `Sensor Zone · 감지 영역` | 물리 반응 없이 진입/이탈만 감지 |
| `Arm-6 · 6축 로봇팔` | 6-DOF + 평행 그리퍼, home 포즈 |

### 5.2 오브젝트·로봇 옮기기 — 드래그 또는 방향키

> **로봇도 오브젝트와 똑같이 옮긴다.** 아래 세 가지 방법(기즈모 드래그·방향키·
> 인스펙터 숫자 입력) 모두 로봇에 그대로 적용된다. 로봇만 다른 점은 §5.2-C에 적었다.

**먼저 대상을 클릭해 선택한다.** 뷰포트에서 클릭하면 아웃라인이 생기고 기즈모가 붙는다
(빈 곳 클릭 = 선택 해제). 현재 선택은 뷰포트 좌하단 상태 줄에 `선택 arm_left`처럼 항상
표시된다 — 아무 반응이 없으면 먼저 이 리드아웃을 확인한다.

**보이는 것을 클릭하면 잡힌다**: 로봇 링크처럼 얇은 대상은 몇 px 빗나가도 실루엣 주변
6px까지는 같은 대상으로 판정한다. 다만 링크 사이의 빈 공간이나 몸통 바깥을 클릭하면
(예전과 같이) 선택이 해제된다 — 선택 없이 방향키를 누르면 안내 토스트가 뜬다.

**(A) 기즈모 드래그**

- `W` 이동 / `E` 회전 / `R` 스케일로 모드를 바꾼다(뷰포트 좌상단 버튼과 동일).
- 기즈모 핸들은 **선택 대상의 보이는 몸통 중심**(아웃라인 상자의 중심)에 붙는다.
  로봇은 좌표 원점이 베이스(바닥)라 예전에는 핸들이 발밑에 그려져 몸통을 아무리 끌어도
  카메라만 돌았다 — 지금은 프리미티브와 같은 자리에서 잡힌다.
- 기즈모 축 화살표를 드래그한다. 스냅 토글을 켜면 격자 5cm·각도 15°로 맞춰진다.
- 드래그 중에는 화면만 따라 움직이고, **손을 떼는 순간 물리에 반영**된다
  (드래그 중 물리를 흔들지 않기 위한 의도적 동작). 커밋되지 않은 드래그(움직임 없는
  클릭, 거부된 스케일 등)는 손을 떼는 순간 원래 배치로 되돌아간다.

**(B) 방향키 (정밀 배치에 편리)**

| 키 | 이동 |
|----|------|
| `←` `→` | 화면 기준 좌우 (카메라를 돌리면 방향도 함께 바뀐다) |
| `↑` `↓` | 화면 기준 앞뒤 |
| `PageUp` `PageDown` | 위/아래(월드 Y) |
| `Shift` + 위 키 | 미세 이동 (1cm) |

기본 이동 폭은 5cm로 스냅 격자와 같아, 반복해서 눌러도 격자에 정렬된 채 움직인다.
방향키 이동도 기즈모와 **같은 경로로 물리에 반영**되므로 결과가 다르지 않다.

**(C) 로봇에만 있는 제약 (정직하게)**

- **베이스는 바닥 아래(y < 0)로 내려가지 않는다.** 로봇 링크는 kinematic이라 바닥과
  겹쳐도 물리가 밀어내지 못한다(dynamic 오브젝트처럼 스스로 튀어나오지 않는다).
  그래서 직접 조작 경로에서 y를 0으로 맞추고 이유를 토스트로 알린다.
- **스케일(`R`)은 프리미티브 전용**이다. 로봇 크기는 URDF에서 유도되므로 스케일 드래그는
  거부되고 원래 배치로 원복된다(토스트로 알린다).
- 치수·Physics 섹션은 로봇에 표시되지 않는다 — URDF `<collision>`에서 유도되기 때문이다.
- **회전(`E`)의 축은 베이스**다. 핸들은 몸통 중심에 그려지지만 로봇은 발밑을 중심으로
  제자리에서 돌아간다(바닥에 선 팔의 자연스러운 회전 — 돌려도 위치는 변하지 않는다).
- 위치·회전은 (위 y 하한 외에는) 제한 없이 편집 가능하며, ⏹ Stop(되감기) 후에도
  **편집한 배치가 유지**된다 (관절만 home으로 복원된다).

> 재생 중에 편집하면 시뮬레이션이 자동으로 일시정지된다.

### 5.3 인스펙터로 정밀 편집

우측 인스펙터에서 선택 대상의 값을 직접 입력한다.

| 섹션 | 편집 항목 |
|-----|----------|
| 이름/ID | 엔티티 id (중복이면 한국어 오류) |
| Transform | 위치 X/Y/Z, 회전(오일러 도 단위 입력 → 내부 쿼터니언) |
| Dimensions | 박스 W/H/L(전체 치수), 구 반지름, 원통·캡슐 반지름+높이 |
| Physics | bodyType, 마찰·반발·밀도, 충돌 그룹, `collidesWith`, sensor·emitEvents·CCD |

값은 **Enter 또는 포커스 아웃에서 확정**된다(타자마다 물리가 재생성되지 않음).
치수를 바꾸면 **메시와 collider가 함께** 갱신된다.

편집 폼은 우측 패널 **맨 위**에 온다 — 로봇을 선택하면 관절 슬라이더·관절 표가 길어지지만
Transform 입력이 그 아래로 밀려나지 않는다.

> 로봇도 이 폼의 이름·Transform(위치/회전)을 그대로 편집할 수 있다. 치수·Physics만
> URDF에서 유도되어 편집 대상이 아니다. 로봇 y 하한은 §5.2-C 참조.

### 5.4 3D 파일 임포트

1. 라이브러리 **⬆ Import** 카드를 클릭하거나, 파일을 뷰포트로 드래그.
2. 지원 형식: **`.glb` · `.gltf` · `.stl` · `.obj`**
3. 다이얼로그에서 설정:
   - **스케일** — 원본 단위 → 미터 (mm 원본이면 `0.001`)
   - **Up-axis** — `Y-up` 또는 `Z-up→변환`
   - **Collider 전략** — `Convex Hull`(기본, 동적 가능) · `AABB` · `Trimesh·정적`
   - **유형** — `Object·동적` 또는 `Static·고정`
4. `Trimesh`를 고르면 유형이 자동으로 Static으로 고정된다(동적 trimesh는 금지 —
   `docs/DATA_MODEL.md` §2).

### 5.5 되돌리기

`Ctrl/Cmd+Z` 또는 커맨드바 `↶`/`↷`. 되돌리기는 검증된 스냅샷에서 씬을 **완전히 재구축**
하므로 상태가 정확히 복원된다. 재생 중 되돌리면 시뮬레이션이 먼저 정지된다.

## 6. 동작 만들기 (Flow Graph)

제어 시퀀스를 노드 체인으로 편집한다. 커맨드바 **‘플로우’** 토글로 페인을 연다.

### 6.1 노드 편집

| 조작 | 동작 |
|-----|------|
| 노드 클릭 | 선택 → 우측 인스펙터에 파라미터 폼 |
| 노드 드래그 | 체인 내 재정렬(삽입선 미리보기) |
| 엣지 위 `＋` | 그 위치에 새 노드 삽입(팔레트 팝오버) |
| `Del` | 선택 노드 삭제(앞뒤 자동 재연결) |
| `Ctrl/Cmd+D` | 복제 |
| 활성 토글 | 노드를 실행에서 제외(순서는 유지, 회색 표시) |
| 휠 / 배경 드래그 | 줌 / 팬, `fit` 버튼으로 전체 보기 |

### 6.2 지원하는 동작(step) 종류

| 종류 | 파라미터 |
|-----|---------|
| `moveJoints` | 관절별 목표값(슬라이더, limits 클램프) · duration · easing |
| `setJoints` | 관절 목표값(즉시 적용) |
| `gripper` | 열기 / 닫기 / 0~1 값 · duration |
| `wait` | 대기 시간(초) |
| `waitForCollision` | 엔티티 쌍 · timeout(초) |
| `label` / `goto` | 반복 구간 표시 / 점프(횟수 지정 가능) |

> `moveToPose`(카테시안 목표)는 IK 백로그다 — 노드는 표시되지만 실행 시 건너뛴다.

### 6.3 항상 유효한 시퀀스

그래프 편집은 **직렬화 불가능한 상태를 만들 수 없다**. 모든 편집은 스키마 검증을 통과할
때만 반영되고, 실패하면 편집이 거부되며 한국어 사유가 표시된다(예: goto가 참조하는 label
삭제 시도). 커맨드바 **`{} JSON`**을 열어 편집 결과가 즉시 반영되는 원본 시퀀스를 확인·
복사할 수 있다.

시퀀스를 수정하면 재생 위치가 처음으로 리셋된다(편집–실행 결정론 유지).

## 7. 자연어로 만들기 (Planner)

문장으로 지시하면 현재 씬에 그라운딩된 시퀀스 초안이 생성된다.

### 7.1 백엔드 선택 (⚙)

| 백엔드 | 특징 |
|-------|------|
| **규칙 기반(오프라인 데모)** — 기본 | 네트워크·키 불필요, 결정론적, 지원 패턴 제한적 |
| **Anthropic API** | 자유로운 문장 해석. 사용자의 API 키 필요 |

Anthropic을 선택하면 API 키와 모델을 입력한다. **키는 이 브라우저의 localStorage에만
저장되고 Anthropic 호출에만 사용된다**(공용 PC에서는 사용하지 말 것 — 다이얼로그에도
같은 경고가 표시된다).

### 7.2 사용법

1. 커맨드바 자연어 입력창에 문장을 쓰고 **✨ 생성**(또는 Enter).
2. **교체 / 이어서** 토글로 기존 플로우를 대체할지 뒤에 덧붙일지 선택한다(기본 교체).
3. 결과는 세 가지 중 하나다:

| 결과 | 화면 |
|-----|------|
| **성공** | 검증을 통과한 노드가 `AI` 배지로 그래프에 로드됨 + "가정" 요약 토스트 |
| **명확화 필요** | 명확화 카드가 뜸 — 옵션 버튼 선택 또는 직접 입력 |
| **실패** | 빨강 토스트 + Console에 사람이 읽을 수 있는 사유 |

### 7.3 규칙 기반 백엔드가 이해하는 문장

```
"박스를 집어"        "box_a를 잡아"      "터치해"      (집기/접촉)
"그리퍼 열어"        "닫아"                            (그리퍼)
"3초 기다려"                                           (대기)
"홈으로"            "원위치"                           (홈 자세)
```

여러 동작은 `그리고` / `하고` / `,` 로 이어 붙일 수 있다.
대상이 여러 개면(`박스를 집어` + box_a·box_b 존재) 명확화 카드로 되묻는다.

### 7.4 안전 규칙 (중요)

- 생성물은 **스키마 검증과 씬 참조 무결성 검사를 통과한 뒤에만** 그래프에 로드된다.
  검증에 실패한 출력은 시뮬레이터에 전달되지 않는다.
- **자동 실행되지 않는다.** 사용자가 검토 후 ▶ Play를 눌러야 시작된다.
- 관절 목표는 로봇의 limits로 클램프된다.
- 어떤 가정을 했는지(대상 해석, 방향어 등)가 토스트와 Console에 표시된다.

## 8. 실행하기 (Orchestration)

### 8.1 재생 컨트롤

| 버튼 | 동작 |
|-----|------|
| **▶ Play** | 시퀀스 재생 시작/재개 |
| **⏸ Pause** | 일시정지(카메라는 계속 조작 가능) |
| **⏹ Stop** | 정지 + 씬을 초기 상태로 리셋 |
| **⏭ Step** | **노드 하나만** 실행하고 다음 노드 경계에서 정지 |
| **속도** | 0.25× / 0.5× / 1× / 2× / 4× |
| **충돌 시 자동 정지** | 예기치 않은 충돌에서 자동 일시정지(기본 꺼짐) |

### 8.2 동기 강조 — 이 도구의 핵심

실행 중 **활성 노드가 세 곳에서 항상 일치**한다:

1. **플로우 그래프** — 활성 노드 테두리·상태 점(대기 회색 / 실행 강조 / 완료 초록 / 오류 빨강)
2. **뷰포트 오버레이**(좌하단) — `● Running · node 3/7 · MoveJoints · simTime 2.34s`
3. **Timeline**(하단 독) — 현재 마커에 커서

이 일치는 자동 게이트(`--expect=orchestration`)가 실제 브라우저 DOM에서 검증한다.

### 8.3 충돌 관찰

충돌이 감지되면 세 가지가 동시에 일어난다:

1. **접촉점 마커** — 부딪힌 **바로 그 지점**에 빨강 구가 뜨고 링이 퍼진다. 로봇 링크
   내부에서 생긴 접촉도 가려지지 않게 그린다(깊이 테스트 없음).
2. **오브젝트 빨강 펄스** — 충돌한 엔티티 전체가 잠깐 붉어진다("무엇이" 부딪혔는지).
3. **Collision Log** — `시간 · 엔티티 쌍 · phase(start/stop) · kind(contact/sensor)` 기록.

> **로봇끼리의 충돌도 감지된다.** 서로 다른 로봇(다른 엔티티)의 링크가 닿으면 이벤트가
> 발행된다. 반면 **한 로봇의 자기 링크끼리는 기본적으로 무시**한다 — URDF 인접 링크는
> 구조상 항상 겹쳐 있어 노이즈가 되기 때문이다. 자기 충돌까지 보려면 그 로봇의
> `selfCollision: true`로 설정한다.
>
> ⚠️ **감지는 되지만 튕겨나지는 않는다.** 로봇 링크는 kinematicPosition 바디라 접촉
> 반력을 받지 않는다 — 두 팔이 닿아도 서로를 밀어내지 않고 계속 지나간다(§11 한계).
> 충돌을 "막고" 싶다면 재생 컨트롤의 **충돌 시 자동 정지** 토글을 켠다. 예기치 않은
> 충돌에서 시뮬레이션이 즉시 멈추고 해당 노드가 오류로 표시된다.
- **로그 행을 클릭**하면 해당 오브젝트에 포커스되고, **그 충돌 시점에 활성이던 노드**가
  강조된다.
- `waitForCollision` 노드가 timeout으로 풀리면 그 노드가 오류(빨강)로 표시된다.

### 8.4 특정 노드부터 재실행

**Timeline 마커** 또는 노드를 클릭하면 그 지점부터 다시 실행한다. 내부적으로는 씬을
처음 상태로 되감은 뒤 목표 노드까지 빨리감기하므로 **결정론적**이다(노드별 스냅샷이
없어 목표 노드 경계에서 ±1 tick 오차가 있을 수 있다 — §11).

## 9. 데이터로 확장하기 (코드 수정 없이)

씬과 제어 시퀀스는 **데이터**다. JSON만 추가하면 된다.

### 9.1 새 씬 추가

1. `src/assets/scenes/<이름>.scene.json` 작성 — 규범은 `docs/DATA_MODEL.md` §5.
   좌표는 **Y-up · 미터 · 라디안**, 회전은 쿼터니언 `[x,y,z,w]`.
2. 충돌을 감지할 collider에는 `emitEvents: true`와 상대 그룹을 `collidesWith`에 넣는다
   (그룹 규약은 `CLAUDE.md` §5). **감지는 양쪽 모두 서로를 지목해야 성립한다.**
3. 동적 바디에 `trimesh` 금지(프리미티브 또는 `convexHull` 사용).
4. `src/main.ts`의 `SCENE_REGISTRY`에 한 줄 추가하면 프리셋 select에 나타난다.
   등록 없이도 📂 업로드로 바로 열 수 있다.

### 9.2 새 시퀀스 추가

`src/assets/sequences/<이름>.sequence.json`에 `ControlSequence`를 쓴다
(`docs/DATA_MODEL.md` §6). robot·joint·엔티티 참조는 **씬에 실제 존재해야** 검증을
통과한다.

최소 예:

```json
{
  "id": "my-sequence",
  "robot": "arm",
  "steps": [
    { "kind": "gripper", "state": "open", "durationSec": 0.4 },
    { "kind": "moveJoints", "targets": { "joint2": 0.55, "joint3": 1.85 },
      "durationSec": 2.0, "easing": "easeInOut" },
    { "kind": "waitForCollision", "between": ["arm", "box_a"], "timeoutSec": 6 },
    { "kind": "gripper", "state": "close", "durationSec": 0.5 }
  ]
}
```

`.claude/commands/new-scene.md`, `add-control-step.md`에 상세 절차가 있다.

## 10. 개발자용

### 10.1 검증

```bash
npm run verify     # typecheck + lint + 단위 테스트(vitest)
npm run gate       # 빌드 + 주요 브라우저 게이트 일괄 실행
```

개별 브라우저 게이트(Playwright chromium 필요 — `npx playwright install chromium`):

```bash
npm run build
node scripts/gate-browser.mjs --expect=orchestration
node scripts/gate-browser.mjs --expect=planner        # 등
```

게이트는 `dist/`를 실제 브라우저에 띄워 물리·UI 어서션을 검증하고
`gate-screenshot.png`를 남긴다. 사용 가능한 `--expect` 값은 `README.md` 표 참조.

### 10.2 Docker

호스트 OS·Node 버전과 무관하게 동일한 결과를 얻는다. 이미지 안에서 `npm ci` →
`tsc --noEmit && vite build` → nginx 서빙까지 끝나므로, 필요한 건 Docker뿐이다.

**구성 파일**

| 파일 | 역할 |
|-----|------|
| `Dockerfile` | 멀티스테이지 — `deps` → `verify` / `build` → `runtime`(nginx) / `dev`(Vite) |
| `docker/nginx.conf` | 정적 서빙(gzip, 해시 자산 장기 캐시, `.urdf` MIME, index 무캐시) |
| `docker-compose.yml` | `app`(프로덕션) · `dev`(HMR) · `verify`(CI) 서비스 |
| `.dockerignore` | `node_modules`·`dist`·`.git` 등 제외 (호스트 바이너리 유입 방지) |

**프로덕션 실행**

```bash
docker compose up -d              # 또는 npm run docker:up
# → http://localhost:8080
docker compose down               # 또는 npm run docker:down
```

포트 변경: `APP_PORT=9000 docker compose up -d`

**개발 (소스 수정 → 즉시 반영)**

```bash
docker compose --profile dev up dev    # 또는 npm run docker:dev
# → http://localhost:5173  (소스는 bind mount, HMR 동작)
```

컨테이너 안에서는 파일 감시가 폴링으로 전환된다(`VITE_USE_POLLING=true`) — bind mount는
호스트의 inotify 이벤트가 전달되지 않기 때문이다. 호스트에서 직접 `npm run dev`를 돌릴
때는 기본(네이티브 감시)이 그대로 쓰인다. `node_modules`는 익명 볼륨으로 격리되어 호스트의
OS별 바이너리가 컨테이너로 새지 않는다.

**검증 (컨테이너 안에서 CI)**

```bash
docker compose --profile ci run --rm verify   # 또는 npm run docker:verify
# typecheck + lint + vitest 724개
```

빌드 단계에서 검증까지 하려면 `docker build --target verify .` — 실패하면 이미지가
만들어지지 않는다.

**컨테이너 배포 형상 검증(실브라우저)**

```bash
docker compose up -d
node scripts/verify-container.mjs             # 또는 npm run docker:check
# → Rapier 초기화 · 물리 진행 · URDF 로봇 로드 · 시퀀스 실행 + 충돌 감지 · 페이지 오류 0
```

`gate-browser.mjs`가 자체 vite preview를 띄우는 것과 달리, 이 스크립트는 **떠 있는 컨테이너
URL을 직접 친다** — nginx 설정·MIME·에셋 경로까지 포함한 실제 배포 형상을 검증한다.
호스트에 Playwright chromium이 필요하다(`npx playwright install chromium`).
다른 포트를 쓴다면 인자로 준다: `node scripts/verify-container.mjs http://localhost:9000`

> **브라우저 게이트는 컨테이너 안에서 돌리지 않는다.** 이미지를 가볍게 유지하려고
> Playwright 브라우저 다운로드를 막아 두었다(`PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1`).
> `npm run gate`는 호스트에서 실행한다.

**이미지 정보** — 런타임 이미지는 `nginx:1.27-alpine` + 정적 번들뿐이라 작고, Node 런타임을
포함하지 않는다. 30초 간격 헬스체크가 붙어 있어 `docker ps`에 `(healthy)`로 표시된다.

### 10.3 자동화 훅 `window.__sim`

브라우저 콘솔이나 자동화 스크립트에서 시뮬레이터를 직접 조작할 수 있다:

```js
window.__sim.engine.state            // 'idle' | 'playing' | 'paused'
window.__sim.robots.setJoint('arm', 'joint1', 0.5)
window.__sim.orchestrator.play()
window.__sim.orchestrator.statuses() // 노드별 실행 상태
window.__sim.planner.generate('box_a를 집어')
window.__sim.collision.recent(20)
```

Rapier·three.js 심볼은 노출되지 않는다(계층 경계 유지 — `CLAUDE.md` §3).

## 11. 알아둘 한계

정직한 현재 상태(자세한 배경은 `README.md` 한계 절, `docs/PRD.md` §6):

- **파지 물리 없음** — 그리퍼는 관절 개폐일 뿐이라 마찰로 물체를 집어 드는 동작은
  시뮬레이션되지 않는다. 픽앤플레이스 데모는 "밀기"로 구현되어 있다.
- **IK 없음** — 관절 공간 직접 제어만 지원한다. 자연어 플래너의 도달 자세도 정확한 역기구학이
  아니라 휴리스틱이다.
- **충돌은 감지되지만 반력은 없다** — 로봇 링크는 kinematicPosition 바디라 접촉해도
  밀려나지 않는다. 두 팔이 부딪히면 이벤트·마커·로그로 확실히 표시되지만 물리적으로는
  서로를 통과한다. 충돌에서 멈추게 하려면 **충돌 시 자동 정지** 토글을 쓴다.
  (접촉 반력이 필요해지면 물리 계층만 MuJoCo로 교체하는 경로가 설계에 있다 — CLAUDE.md §7.)
- **자기 충돌은 근사** — 한 로봇 안의 링크끼리는 기본적으로 무시한다(URDF 인접 링크가
  항상 겹치기 때문). `selfCollision: true`로 켤 수 있지만 인접 링크 쌍을 걸러내지 않아
  상시 접촉이 함께 보고된다.
- **빠른 링크 충돌 누락 가능** — 로봇 링크는 kinematic 바디라, 매우 빠른 이동은 얇은 물체와의
  충돌을 놓칠 수 있다. 감지가 중요한 구간은 속도를 낮추거나 감지 영역(sensor)을 두껍게 한다.
- **플로우 편집은 Undo 대상이 아니다** — `Ctrl+Z`는 씬 편집에만 적용된다.
- **재실행 정밀도** — 노드부터 재실행은 항상 처음부터 되감아 빨리감기하며 경계 ±1 tick
  오차가 있다.
- **임포트 메시는 세션 한정** — 저장한 씬 JSON에 메시 데이터가 포함되지 않는다.
- **규칙 기반 플래너 범위** — 지원 문장 패턴이 §7.3으로 제한된다(자유로운 지시는 Anthropic 백엔드).
- **안전 인증 부적합** — 교육·프로토타입·데모용이다. 실제 로봇 안전 검증에 사용하면 안 된다.

## 12. 문제 해결

| 증상 | 확인할 것 |
|-----|----------|
| 화면이 검고 아무것도 안 보임 | 브라우저 콘솔에 `Rapier ready`가 찍혔는지, WebGL2 지원 여부 |
| 씬 로드 실패 오버레이 | 표시된 한국어 검증 오류의 JSON 경로를 보고 해당 필드 수정 |
| 충돌이 감지되지 않음 | 양쪽 collider의 `collidesWith`가 서로를 포함하는지, `emitEvents: true`인지 (`CLAUDE.md` §5) |
| 로봇 두 대가 겹쳐 지나감 | 감지는 되지만 kinematic 로봇은 반력이 없어 밀려나지 않는다(§11). Collision Log·접촉점 마커를 확인하고, 멈추려면 **충돌 시 자동 정지**를 켠다 |
| 한 로봇의 링크끼리 충돌이 안 잡힘 | 기본 동작이다(인접 링크 노이즈 억제). 필요하면 해당 로봇 `selfCollision: true` |
| 로봇이 누워 있음 | URDF up-axis. 임포트 시 `Z-up→변환` 선택 확인 |
| 시퀀스가 시작되지 않음 | 생성물은 자동 재생되지 않는다 — ▶ Play를 눌렀는지, Console에 검증 오류가 없는지 |
| `waitForCollision`이 timeout | 도달 자세가 실제로 대상에 닿는지(그래프에서 목표 관절값 조정), timeout 값 |
| 자연어 생성이 계속 실패 | 규칙 기반 백엔드의 지원 패턴(§7.3) 확인, 또는 ⚙에서 Anthropic 백엔드로 전환 |
| Anthropic 백엔드 인증 오류 | ⚙에서 API 키 재확인 (키는 localStorage `robotSimWeb.planner`에 저장됨) |
| 편집했는데 물리에 반영 안 됨 | 기즈모는 드래그를 놓는 순간 반영된다. 인스펙터 값은 Enter/포커스 아웃에서 확정 |
| `docker compose up` 실패 — daemon 연결 오류 | Docker Desktop(Windows/macOS)이 실행 중인지, Linux는 `sudo systemctl start docker` |
| 8080 포트 충돌 | `APP_PORT=9000 docker compose up -d` 로 변경 |
| 컨테이너는 떴는데 화면이 비어 있음 | `docker compose logs app` 확인 후 `npm run docker:check`로 배포 형상 검증 |
| Docker dev에서 수정이 반영 안 됨 | dev 프로파일로 띄웠는지 확인(`--profile dev`). 폴링 감시는 반영까지 최대 ~0.3초 |
| 이미지 빌드가 오래 걸림 | 첫 빌드만 `npm ci`를 수행한다. 이후 소스만 바뀌면 의존성 레이어는 캐시된다 |
