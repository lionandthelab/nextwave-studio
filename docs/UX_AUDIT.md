## 0. 한 문단 요약

**엔진은 프로급, 셸은 프로토타입이다.** 고정 timestep 결정론, 무손실 그래프↔시퀀스 변환
불변식, 노드 단위 결정론적 재실행, human-in-the-loop 플래너 게이트 — Isaac Sim에도 n8n에도
없는 조합이 이미 동작한다. 트라이페인(뷰포트↔그래프↔타임라인) 동기화도 설계서가 약속한
수준으로 실제 구현되어 있고, 색 대비는 실측 18종 전부 WCAG AA를 통과한다. 그러나 그 가치에
도달하는 길이 거의 모두 막혀 있다. 뷰포트 크기가 `(창너비−530)×(창높이−506)`이라는 **상수
차감 함수**로 고정되어 1366×768 노트북에서 3D 뷰포트가 화면의 20.9%로 줄고, 커맨드바는
1600px부터 컨트롤이 서로 **물리적으로 겹쳐** 이 제품의 헤드라인 기능인 자연어 입력창과
Undo/Redo가 클릭 불가능해진다. 저장 버튼은 씬만 저장하고 **시퀀스를 버리며**, 새로고침 한
번에 모든 작업이 사라진다. 씬에 넣은 오브젝트를 지울 UI가 없고, 키보드로는 오브젝트를 선택할
방법조차 없다. 격차는 렌더링 품질이 아니라 **문서(document) 모델과 제품 셸의 부재**이며,
대부분 백엔드 없이 닫을 수 있다.

**종합 점수: 2.0 / 5.0**

## 1. 평가 방법

추측을 배제하기 위해 실제 앱을 Playwright로 부팅해 계측했다.

| 항목 | 내용 |
|---|---|
| 스크린샷 | 6개 해상도 × 22개 상태 (`docs/ux-audit/*.png`) |
| 레이아웃 실측 | 패널별 `getBoundingClientRect`, 뷰포트 점유율, 요소 간 겹침 좌표 |
| 대비 실측 | 합성 배경 기준 WCAG 상대휘도 계산, 텍스트 18종 |
| 확장성 실측 | 엔티티 60개 추가 · 노드 42개 삽입 후 FPS/DOM/클리핑 |
| 코드 대조 | `src/ui` 전량 + `docs/UX_DESIGN.md` 규범 대비 구현 격차 |
| 팀 구성 | 5개 렌즈 병렬 진단 후 교차 검증 → 중복 통합 |

**측정 정정**: 초기 스크립트가 보고한 "접근 가능한 이름 없음 5개"는 **3개가 오탐**이었다.

강제하는 덕분에 **이름 누락은 실질적으로 0건**이다. 나머지 2개는 `display:none` 파일 입력으로
무해하다. 이 영역은 잘 되어 있다.

## 3. 이미 잘 되어 있는 것 (건드리지 말 것)

비판만 있는 보고서는 방향을 주지 못한다. 실측으로 확인한 강점부터 적는다.

| 강점 | 근거 |
|---|---|
| **트라이페인 동기화가 실제로 작동** | `orchestrator.onNodeStatus` → `flowCanvas.setStatuses` + `timelinePanel.setActiveIndex` + `refreshOverlay`가 rAF 외 이벤트 직후에도 호출되어 한 프레임도 어긋나지 않는다 ([main.ts:1408-1416](../src/main.ts#L1408-L1416), [:2250](../src/main.ts#L2250), [:2343](../src/main.ts#L2343)). `docs/UX_DESIGN.md` §1의 핵심 원칙이 **달성됐다** |
| **충돌 로그 ↔ 노드 ↔ 타임라인 역방향 연동** | 행 클릭이 `timeSecToNodeIndex`로 당시 활성 노드를 되찾아 캔버스 선택 + 타임라인 커서를 옮기며, 재생 상태의 두 번째 진실이 되지 않도록 읽기 전용으로 설계됨. 프로급 디버깅 어포던스 |
| **human-in-the-loop 강제 (불변식 §2.9)** | 생성 결과는 자동 재생되지 않고, 검증 통과본만 그래프에 로드된다. `clarify`/`error`는 시뮬레이터로 보내지 않는다 |
| **API 키 벽이 없다** | 기본 백엔드가 규칙 기반 오프라인이라 첫 사용자가 키 없이 전체 플로우를 경험한다. 첫 실행 장벽 설계로서 옳은 선택 |
| **색 대비** | 샘플 18종 **전부 AA 통과**, 최저 5.86:1. 상태를 색만으로 전달하지 않는 규약(점 + 텍스트 라벨 병행)도 일관 적용 |
| **광과민성 안전** | 펄스 0.71Hz / 0.83Hz로 WCAG 2.3.1 임계(3Hz)에 크게 미달. 충돌 펄스는 600ms 일회성 |
| **명확화 카드 구현 품질** | `role=dialog` + 첫 포커스 이동 + Escape + Tab 순환 트랩까지 완비 ([clarify-card.ts:156-222](../src/ui/feedback/clarify-card.ts#L156-L222)). 화면에 띄우는 경로만 막혀 있고 모듈은 완성품 |
| **충돌 로그의 성숙한 구현** | 500행 링버퍼 + 엔티티 필터 + 자동스크롤 정지 + 행 클릭 포커스 |
| **플로우 편집 거부 피드백** | 무효 편집은 한국어 사유와 함께 거부되고 그래프는 불변으로 남는다(불변식 §2.8). 노드 폼에 `role=alert` 인라인 오류 |
| **검증 게이트 문화** | Playwright 게이트 7종(`gate:orchestration`/`gate:planner`/…). B2B 신뢰 신호로 쓸 수 있는 자산 |
| **성능 여유** | 노드 42개 삽입 후에도 59.7 FPS. 엔티티 60개 추가 시 48.5 FPS(물리 비용, UI 아님) |

#### C-1. 뷰포트 면적이 창 크기의 상수 차감 함수다 — 주인공이 화면의 1/5

*(F-IA-01, F-IA-05, F-IA-04, F-IA-06)*

세로 크롬(커맨드바 44 + 독 211 + 그래프 241 + 스플리터 10) 합이 **506px 고정**, 가로 크롬
(좌 240 + 우 280 + 스플리터 10)이 **530px 고정**이다. 창이 작아질수록 뷰포트만 손해 본다.

| 창 크기 | 뷰포트 실측 | 점유율 | 검산 |
|---|---|---|---|
| 1920×1080 | 1390×574 | 38.5% | 1080−506=574 ✓ |
| 1600×900 | 1070×394 | 29.3% | 900−506=394 ✓ |
| 1440×900 | 910×394 | 27.7% | 1440−530=910 ✓ |
| **1366×768** | **836×262** | **20.9%** | 768−506=262 ✓ |
| **1280×720** | **750×214** | **17.4%** | 720−506=214 ✓ |
| 1024×768 | 494×262 | 16.5% | 1024−530=494 ✓ |

1366×768에서 3D 뷰포트는 **3.19:1 레터박스 띠**가 되어 로봇의 세로 작업 공간(팔 리치, 낙하,
그리퍼 접근)을 관찰할 수 없다. 시뮬레이터의 존재 이유가 무력화된다.

**"스플리터로 조절하면 되지 않나"에 대한 반증**: 최소값 합이 이미 크다
(`left.min 180` / `right.min 220` / `dock.min 120` / `flowGraph.min 200`).
1366×768에서 모든 스플리터를 최대한 끌어도 **41.5%가 상한**이고, 그마저 매 세션 손으로 다시
끌어야 한다(C-4: 영속 없음). 우 패널은 접는 API 자체가 없다.

**추가 결함**: 독은 211px를 상시 점유하는데 Timeline 콘텐츠는 **~58px**뿐이고
(스크린샷 `10`/`20`/`30`에서 130~132px 공백 확인), `▾ 접기`를 눌러도 **뷰포트는 1px도
커지지 않는다** — 접기가 독 내부 body만 0으로 만들고 그리드 슬롯 높이는 그대로다
([dock.ts:90](../src/ui/dock/dock.ts#L90) vs [workspace.ts:454](../src/ui/workspace.ts#L454)).

**제안**
```ts
// workspace.ts — 상수를 정책으로
export const VIEWPORT_MIN_H_PX = 240;
export const DOCK_H_CSS = 'clamp(112px, 16vh, 280px)';
export const FLOW_H_CSS = 'clamp(148px, 22vh, 380px)';

centerWrap.style.display = 'grid';
centerWrap.style.gridTemplateRows =
  `minmax(${VIEWPORT_MIN_H_PX}px, 1fr) auto var(--rsw-fg-h, ${FLOW_H_CSS})`;
```
+ 독 기본 접힘(탭바 28px, Timeline 콘텐츠는 탭바 인라인 스트립으로 이동 — 정보 손실 0)
+ `setDockCollapsed` API 신설 및 `main.ts` 배선
+ 하한 재산정: `dock.min 120→28`, `flowGraph.min 200→56`, `right.min 220→200`

**예상 효과**: 1366×768 점유율 20.9% → **33.6%**(clamp만) → **50.2%**(독 접힘 포함).
스플리터 최대 조절 시 상한 41.5% → **67.9%**.

**비용: M**

#### C-2. 커맨드바 겹침은 미관이 아니라 기능 소실이다

*(F-IA-02, F-UX-01, F-PRO-04)*

44px 한 줄에 **22개 요소(인터랙티브 18개)** 를 넣었고, 겹친 영역에서는 DOM 뒤 형제가 위에
그려져 **클릭을 가로챈다**.

| 창 크기 | 겹침 건수 | 실제 피해 |
|---|---|---|
| 1920 | 1 | 경미 |
| 1600 | 8 | `✨ 생성`이 `⏭ Step`에 49px 겹침 |
| 1440 | 13 | 자연어 입력창 소실 |
| 1366 | 17 | `💾 저장`이 `▶ Play`와 겹침 |
| **1280** | **20** | `↶`/`↷`(폭 ~28px)가 **100% 피복 → 완전 클릭 불가**. `💾 저장`(폭 ~62px)의 73% 피복 |
| 1024 | 24 | `barScrollW 1106 > clientW 1024` → `⚙`가 화면 밖, **영구 도달 불가** |

**원인은 정확히 세 줄이다** ([scene-controls.ts:157](../src/ui/command-bar/scene-controls.ts#L157),
[:162-165](../src/ui/command-bar/scene-controls.ts#L162-L165),
[:171](../src/ui/command-bar/scene-controls.ts#L171)):
`left`/`right`가 `flexShrink:0`인데 `center`만 `minWidth:0` + `justifyContent:'center'`다.
그래서 center 컨텐츠가 **좌우 대칭으로 넘쳐** 양쪽 이웃 위에 얹힌다. `bar`에 `overflow`
지정이 없어 밖으로 그려지고, `.ui-btn`은 `white-space: nowrap`이라 줄바꿈도 안 된다.

**대가**: 1440px 이하 — 즉 **노트북 사용자 전원** — 에게서 이 제품의 헤드라인 기능인 자연어
입력이 사라진다. 더 나쁜 것은 실패가 조용하지 않다는 점이다: 오클릭이 `⏭ Step`을 눌러 시뮬이
한 노드 진행하므로, 사용자는 "생성을 눌렀더니 로봇이 제멋대로 움직였다"고 해석한다.
데모·발표 환경(보통 1280/1600)에서 차별화 기능이 화면에 없다.

**제안** — (a)만으로 겹침이 **구조적으로 불가능**해진다
```ts
bar:    { flexWrap: 'nowrap', overflow: 'hidden' }
left:   { flexShrink: '1', minWidth: '0', overflow: 'hidden' }
center: { flexShrink: '1', minWidth: '0', overflow: 'hidden',
          justifyContent: 'flex-start' }   // ← 'center' 제거가 핵심
right:  { flexShrink: '0' }
```
(b) 2행 커맨드바 — `barHeightPx: 44 → 76`. `docs/UX_DESIGN.md` §2 다이어그램이 이미 3줄로
그려 놓은 구조다. 비용 32px는 C-1의 독 접힘(+183px)으로 상쇄하고도 남는다
(c) 우선순위 오버플로 `«` 메뉴: `P0 ▶⏸⏹` > `P1 🗣+생성` > `P2 Scene▾` > … > `P6 유틸`
(d) 아이콘 전용 모드(`W<1100`) — `makeButton`이 `title`/`aria-label`을 이미 유지하므로
**접근성 손실 0으로 214px 회수**

**비용: M** (a만 하면 S)

#### C-3. 작업물이 3중으로 소실된다

*(F-PRO-01, F-PRO-02, F-UX-09, F-IA-08)*

| 소실 경로 | 근거 |
|---|---|
| **💾 저장이 시퀀스를 버린다** | [scene-controls.ts:419-434](../src/ui/command-bar/scene-controls.ts#L419-L434)가 `api.currentSpec()`(SceneSpec)만 직렬화. 업로드 쪽은 `{scene, sequence}` 봉투를 받는데([main.ts:605-608](../src/main.ts#L605-L608)) 저장 쪽은 봉투를 만들지 않는 **비대칭**. 임포트 메시도 내장되지 않아 다른 세션에서 사라진다 |
| **새로고침이 전부를 지운다** | `localStorage`/`sessionStorage` **완전히 빈 상태**(직접 실측). 유일한 사용처는 플래너 설정 1건. 씬·시퀀스·레이아웃·선택·줌·undo 스택 전부 휘발 |
| **경고가 없다** | `confirm(` / `beforeunload` / `dirty` / `저장 안 됨` — repo 전체 **0건**(직접 grep 확인). 씬 프리셋 드롭다운을 "잠깐 보려고" 바꾸면 30분 작업이 무음으로 증발 |

이 제품의 핵심 산출물은 씬이 아니라 **시퀀스**다. 30분간 플래너와 그래프로 만든 시퀀스가
"저장했다"는 감각과 함께 사라진다. 프로 툴에서 가장 용서받지 못하는 실패 유형이다.

`docs/UX_DESIGN.md` §7이 규정한 "변경 시 ● 저장 안 됨, 저장 후 체크"는 미구현이다.

**제안**
1. `SceneControlsApi`에 `currentDocument(): {scene, sequence, assets?}` 추가 → 봉투 저장.
   확장자 `.scene.json` → `.workcell.json`으로 "이 파일이 전부다"를 이름으로 약속
2. IndexedDB 자동저장(편집 커밋 훅에 디바운스) + 부팅 시 "이전 작업 복원" 배너

#### C-5. 키보드로 오브젝트를 선택할 수 없다 — 앱의 절반이 닫혀 있다

*(F-A11Y-01, F-A11Y-02)*

엔티티 선택 경로는 (a) 3D 캔버스 클릭 raycast, (b) 인스펙터 목록 클릭 — **둘 다 키보드
도달 불가**다. 인스펙터 행은 `tabIndex`도 `role`도 없는 `div`이고
([inspector.ts:540-575](../src/ui/inspector/inspector.ts#L540-L575)), WebGL 캔버스에는
`tabIndex`가 부여되지 않는다. 선택이 안 되면 트랜스폼 편집·기즈모·관절 패널이 전부 렌더되지
않으므로 **씬 편집이 통째로 닫힌다**. WCAG 2.1.1 Keyboard (Level A) 명백한 실패.

같은 파일 [:367](../src/ui/inspector/inspector.ts#L367)이 role 없는 div에 `aria-selected`를
거는데, 이 속성은 해당 role에서 무효라 스크린리더가 무시한다.

플로우 그래프도 같다 — `<g role="button" aria-label="…">` 14개에 **`tabIndex`가 없어**
탭 순서에 등장하지 않는다. aria만 있고 조작 불가한 유령 버튼이다.

**제안**: 인스펙터 목록을 roving-tabindex `listbox`로 승격(`role=listbox`/`role=option`,
↑↓·Enter·Home/End) — 이때 기존 `aria-selected`가 비로소 유효해진다. 캔버스에 `tabIndex=0` +
`role="application"` + 목록 위임을 안내하는 `aria-label`. 플로우 노드/삽입점에도 roving
tabindex + SVG 루트 keydown 위임.

**비용: M** — 다른 접근성 작업의 **전제조건**이다. 이걸 안 하면 폼 라벨링을 완벽히 고쳐도
그 폼에 도착할 방법이 없다.

#### C-17. 씬 구성 플로우에 드래그 프리뷰가 없다

*(F-UX-06)*

Box 카드를 어두운 뷰포트 위로 끌고 가는 동안 **아무 시각 피드백이 없다**.
[main.ts:2813-2820](../src/main.ts#L2813-L2820)의 `dragover`는 `preventDefault()`와
`dropEffect='copy'`만 한다. 바닥 레이캐스트도 프리뷰 메시도 없다.
[library.ts:16](../src/ui/library/library.ts#L16) 주석은 "별도 프리뷰는 뷰포트의 반투명
고스트가 담당"이라며 책임을 넘기지만 뷰포트에 그 구현이 없다.

`docs/UX_DESIGN.md` §3.3은 "드래그 중 반투명 고스트를 바닥 레이캐스트 지점에 표시"를 명시한다.

사용자는 놓고 → 확인하고 → 기즈모로 다시 옮긴다(3단계). 오브젝트 10개 씬이면 20회 이상의
불필요한 교정이 생기고, **삭제가 없으므로**(C-4) 잘못 놓인 것들이 누적된다.

**제안**: `render`에 `beginPlacementPreview` / `updatePlacementPreview(clientX, clientY)` /
`endPlacementPreview()`. `ui`는 좌표만 넘기므로 계층 규칙 유지, 프리뷰는 순수 시각 요소라
불변식 §2.1의 명시적 예외에 해당한다.

**비용: M**

## 7. 세 문장 결론

이 앱의 문제는 **만들다 만 것이 아니라, 만든 것이 보이지 않는 것**이다. 결정론 물리·무손실

### 8.6 남은 것

의도적으로 범위 밖에 둔 항목이며 `EXPERIMENTS.md` "Phase 11 § 남은 것"에 근거가 있다.

- **물리 스텝 시간(ms/frame)** — `core/engine`이 `EngineTickInfo.physicsMsPerFrame`을 노출해야
  한다. 계층 규칙상 `ui`가 측정할 수 없어 현재는 대시(—)로 표시하고 0으로 위장하지 않는다.
- **3D 배치 고스트** — `render`에 `beginPlacementPreview/updatePlacementPreview/endPlacementPreview`
  추가 필요.
- **문서 라이브러리 UI** — `document.ts`에 IndexedDB 컬렉션은 있으나 씬 select의 "내 문서"
  optgroup 미구현.
- **레이아웃 프리셋 메뉴** — `workspace.applyPreset()`은 구현, 노출 UI 미구현.
- **URL fragment 공유 링크** — 정적 호스팅에서 가능한 최대치로 백로그.
