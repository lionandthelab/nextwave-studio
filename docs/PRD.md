# PRD — robot-sim-web

## 1. 목적

IsaacSim의 핵심 경험을 브라우저에서 가볍게 재현한다. 사용자는 (1) 로봇과 사물을 배치해
가상 환경을 구성하고, (2) 로봇에 제어 시퀀스를 넣어 재생하며, (3) 로봇과 사물의 충돌을
실시간으로 감지·확인한다. 무겁고 GPU가 필요한 풀 시뮬레이터가 아니라, **정적 호스팅으로
배포되는 브라우저 완결형 도구**를 지향한다.

## 2. 문제 정의

- Isaac Sim/Isaac Lab은 강력하지만 RTX GPU와 무거운 설치가 필요하고, 웹은 WebRTC
  스트리밍 방식이라 인프라 부담이 크다. 교육·프로토타입·데모 목적엔 과하다.
- Gazebo/Webots 등 기존 도구는 데스크톱 중심이거나 웹 통합이 뷰어 수준에 머문다.
- "브라우저에서 링크만 열면 로봇 동작과 충돌을 바로 볼 수 있는" 가벼운 대안이 필요하다.

## 3. 대상 사용자 (초기)

- 로봇 제어 시퀀스를 시각적으로 검증하려는 개발자/교육자
- 충돌 감지 로직·워크셀 레이아웃을 빠르게 실험하려는 사람
- 로봇공학 개념(관절, 충돌, 워크스페이스)을 웹으로 가르치려는 교육 콘텐츠 제작자

## 4. 핵심 사용자 시나리오

1. **씬 구성** — 바닥 위에 로봇 팔(URDF)과 박스 몇 개를 배치한다. 파일 업로드 또는
   샘플 SceneSpec 선택으로 로드된다.
2. **시퀀스 재생** — "관절 A를 90°로 2초간 이동 → 그리퍼 닫기 → 대기" 같은 시퀀스를
   재생/일시정지/스텝한다.
3. **충돌 확인** — 로봇 링크가 사물이나 벽에 닿는 순간 로그 패널에 `start/stop` 이벤트가
   찍히고, 해당 오브젝트가 하이라이트된다.

## 5. 요구사항

### 5.1 기능 요구사항 (MVP)

- FR-1: `SceneSpec`(JSON)으로 환경·로봇·사물을 선언적으로 로드한다.
- FR-2: URDF 로봇을 로드해 렌더링하고, 관절을 개별 제어할 수 있다.
- FR-3: 프리미티브(box/sphere/capsule/cylinder) 및 mesh 사물을 물리 바디로 생성한다.
- FR-4: 고정 timestep 물리 루프에서 중력·충돌·강체 운동을 시뮬레이션한다.
- FR-5: `ControlSequence`(선언적 step 배열)를 재생/일시정지/리셋/단일 스텝한다.
- FR-6: 로봇–사물, 로봇–환경 충돌을 EventQueue로 감지하고 이벤트 스트림으로 노출한다.
- FR-7: sensor 영역(감지만, 물리 반응 없음)을 정의할 수 있다.
- FR-8: 충돌 이벤트를 UI 로그 패널에 시간·엔티티 쌍·phase로 표시한다.
- FR-9: 카메라 orbit/pan/zoom, 재생 컨트롤, 씬/시퀀스 로드 UI.

### 5.2 비기능 요구사항

- NFR-1: 백엔드 불필요. 정적 파일 호스팅으로 배포 가능.
- NFR-2: 대표 씬(로봇 1 + 사물 ~10)에서 물리 스텝이 프레임 예산 내 유지.
- NFR-3: 고정 timestep으로 재현 가능한 결과(동일 입력 → 동일 궤적) 지향.
- NFR-4: 물리 계층 교체 가능(Rapier → MuJoCo WASM)하도록 경계 격리 (CLAUDE.md §7).
- NFR-5: TypeScript strict, 핵심 로직 단위 테스트 가능.

## 6. 범위 밖 (Non-goals) — MVP

명시적으로 **하지 않는다.** 나중에 재검토한다.

- 고정밀 접촉 물리/파지(grasping) 사실성 — MuJoCo 업그레이드 경로에서 다룬다.
- 강화학습 훈련 루프, 대규모 병렬 환경.
- 센서 시뮬레이션(카메라 이미지, LiDAR 포인트클라우드, depth).
- 역기구학(IK) 자동 풀이 — MVP는 관절 공간 직접 제어. (IK는 로드맵 후반.)
- 실기 로봇 연동(ROS/serial/websocket) — 아키텍처는 열어두되 MVP 구현 안 함.
- 멀티유저 협업 편집, 클라우드 저장.
- 물리 정확도 인증(안전 검증 용도로 쓰기엔 부적합함을 명시).

## 7. 성공 기준

- 샘플 씬 3종(픽앤플레이스, 장애물 회피, 충돌 테스트베드)이 브라우저에서 로드·재생된다.
- 각 씬에서 의도한 충돌이 정확한 시점에 감지되어 로그에 남는다.
- 새 씬/시퀀스를 **코드 수정 없이 데이터만으로** 추가할 수 있다.
- 정적 배포본이 GPU 없는 일반 노트북 브라우저에서 동작한다.

## 8. 리스크와 대응

| 리스크 | 대응 |
|-------|------|
| Rapier 접촉 물리가 조작 작업엔 거칠 수 있음 | MVP는 감지·운동 중심. 정밀 접촉은 MuJoCo 경로로 격리 |
| URDF 다양성(mesh 포맷, xacro) | v1은 표준 URDF+STL/glTF 지원, xacro는 사전 변환 요구 |
| WASM+번들러 이슈 | rapier3d-compat 채택, vite 설정 고정 (CLAUDE.md §9) |
| 브라우저 성능 한계 | collider 단순화 원칙, 고정 timestep, LOD는 후반 |
